# Как воспроизвести эксперименты

Выводы, таблицы и спорные примеры: [EXPERIMENTS.md](../EXPERIMENTS.md).
Запускайте команды из корня репозитория в Python 3.12 с установленными
зависимостями: `python -m pip install -r requirements.txt`.
Код оценки не входит в Docker-образ приложения и не вызывается веб-интерфейсом.

## 1. Пересчёт без ключей, API и Qdrant

```powershell
python -m evaluation.replay
```

Команда проверяет SHA-256 опубликованных отчётов, снимков и разметки,
валидирует выбранные ID, пересчитывает метрики и создаёт JSON/Markdown в
`evaluation/results/replay/`. В Markdown показаны dense-кандидаты, ранжировка,
cosine/rerank scores, состав контекста и полный ответ LLM для каждого запроса.
Это анализ исторических ответов, не повторная генерация.
Ключи, Docker и сеть для этой команды не нужны.

Исходные JSON лежат в `reference/`, их контрольные суммы и исходные имена —
в `reference/manifest.json`. Они сохраняют и неудачные редакции промпта.
`book_search_v4.json` содержит 40 запросов, из которых 15 допущены к метрикам,
и снимок описаний 47 книг. Два дополнительных набора содержат 6 запросов
и одну проверку явной границы года. История изменения меток внутри файлов
не является новой независимой разметкой; оговорки — в отчёте экспериментов.

## 2. Новый полный прогон с внешними API

Нужны действующие `OPENROUTER_API_KEY` и `DEEPSEEK_API_KEY` в `.env`.
Подготовка требует до 47 новых вызовов embeddings. Основной прогон на 15 запросах:
15 embeddings запросов, 15 реранкингов top-10, 30 генераций. SDK может повторять
сетевые попытки. Ограничения бесплатных endpoints и расход токенов действуют.

Запустите отдельный пустой Qdrant для экспериментов:

```powershell
docker run --rm -d --name polka-evaluation-qdrant -p 127.0.0.1:6335:6333 qdrant/qdrant:v1.18.1
python -m evaluation.prepare_index
python -m evaluation.run --limit 15 --contexts 5 10
```

Скрипты используют `127.0.0.1:6335`, независимо от QDRANT_HOST/PORT в `.env`.
Другой отдельный порт задаётся одинаковым `--port` в обеих командах. Порт 6333
отклоняется, чтобы случайно не использовать рабочую базу. Подготовка отказывается
заменять существующую коллекцию. Запускайте её один раз для нового сервера;
для следующих прогонов используйте уже подготовленный индекс.

Описания берутся из `database_evidence_snapshot`, а не генерируются заново.
Вызывается только embedding книг. Коллекция создаётся после подготовки всех
векторов; успешные API-результаты кешируются, чтобы повторить незавершённую
подготовку без лишних вызовов. При сбое записи после создания коллекции используйте
новый пустой оценочный сервер. Рабочую коллекцию приложения не удаляйте.

До и после прогона проверяются состав из 47 книг, исходные поля, снимок описаний,
версии индекса, векторы и хеш индекса. Отличающийся индекс останавливает оценку.
Запросы с непроверенной разметкой не выполняются.

В результатах есть `summary` по всем успешным строкам и `paired_summary` только
по запросам, успешным во всех конфигурациях. Ошибки учитываются отдельно.
На общем этапе HTTP 429 прогон останавливается; оставшиеся запросы не получают
фиктивных нулевых оценок. Успешные результаты остаются в кеше для повтора.

После работы отдельный контейнер можно остановить:

```powershell
docker stop polka-evaluation-qdrant
```

Он создан с `--rm`, поэтому будет удалён вместе с временным индексом.
Рабочий Compose и его том эта команда не затрагивает. Для повторного создания
индекса на тех же данных embedding-кеш можно использовать без новых API-вызовов:
`python -m evaluation.prepare_index --offline`.

## 3. Повторы LLM и режим рассуждений на фиксированных кандидатах

Эти команды не используют Qdrant и OpenRouter. Требуется только ключ DeepSeek.
Каждая делает 15 генераций: пять заданных запросов × три повторения.

```powershell
python -m evaluation.repeat_answers --baseline evaluation/reference/context_comparison.json
python -m evaluation.repeat_answers --baseline evaluation/reference/context_comparison.json --thinking enabled
```

По умолчанию запросы: q008, q029, q005, q012, q039; контекст — `20-to-5`.
Можно задать `--query-ids`, `--configuration` и `--samples`.
Одинаковый sample повторно читает кеш; другой sample вызывает новую генерацию.
Sample не передаётся модели как seed. Режим thinking входит в ключ кеша.
Промпт и модель сверяются с исходным отчётом. Для исторического промпта явно
добавьте `--use-baseline-prompt`; модель должна совпадать с текущей.

## 4. Другие сохранённые эксперименты

На отдельном индексе из шага 2:

```powershell
python -m evaluation.run --limit 15 --prompt-reference evaluation/reference/before_prompt.json
python -m evaluation.run --limit 15 --prompt-reference evaluation/reference/prompt_trial_2.json
python -m evaluation.run --dataset evaluation/book_search_batch_03.json --limit 6 --contexts 5
python -m evaluation.run --dataset evaluation/book_search_year_explicit.json --limit 1 --contexts 5
```

`--prompt-reference` берёт точный system_prompt из сохранённого JSON.
Остальные редакции повторяются аналогично; у первой исторически выполнены
только первые пять запросов (`--limit 5`). Это новые вызовы API, не обещание
дословно повторить прежние ответы. Спорные метки дополнительных запросов
сохранены исторически: сначала прочитайте раздел об интерпретации в EXPERIMENTS.md.

У `evaluation.run` и `repeat_answers` есть `--offline`: новые внешние вызовы
запрещены, необходим уже заполненный локальный кеш. В отличие от `replay`,
`run --offline` всё равно требует оценочный Qdrant для проверки индекса.
Кеш внешних запросов в репозиторий не включён; сохранённые отчёты не являются
этим кешем. Для проверки сразу после клонирования используйте именно `replay`.

Новые JSON/Markdown и кеш пишутся в игнорируемые `evaluation/results/` и
`evaluation/cache/`. `--output-dir` и `--cache-dir` позволяют выбрать другие пути.
Не указывайте `reference/` как output-dir: там находятся исторические данные.
Сохранённый отчёт может содержать текст пользовательских запросов и книг;
проверяйте новые результаты перед самостоятельной публикацией.

## Метрики, стоимость и проверки кода

Формулы — в [EXPERIMENTS.md](../EXPERIMENTS.md), реализация — `metrics.py`.
Качество текста объяснений автоматически не оценивается. Числа отражают
согласованную тогда разметку; неоднозначные случаи требуют ручного чтения.

При желании `run` принимает `--input-usd-per-million` и
`--output-usd-per-million`. Без цен стоимость равна null, не нулю. Оценка по
заданным ценам не учитывает скидки на кеш, embedding/rerank, инфраструктуру
и оплаченные неуспешные попытки. Длительности из кеша — исторические измерения,
а не текущая задержка приложения.

```powershell
python -m unittest discover -s tests -v
```

Тесты проверяют формулы, пропуски и ошибки, целостность снимка, безопасную
подготовку отдельного индекса и неизменность контекста при повторной генерации.
Они не расходуют API-лимиты. Живой прогон зависит от доступности моделей и ключей.
